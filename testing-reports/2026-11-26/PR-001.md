## Assessment

The local-first FastAPI/SQLite architecture is appropriate for feasibility research.
Pure evaluation functions, explicit manual actuators, a disabled authorized actuator,
per-experiment privacy consent, and separate demo experiments fit the product vision.
There is no justification yet for replacing the stack, adding SaaS infrastructure,
or building new platform integrations. Copy Taste, Blend, monitoring, and marketplace
features should remain deferred until observation and comparison are trustworthy.

The implementation is useful as a research workbench, but **not ready to produce an
accepted EXP-001 result without correction and manual validation**. The main risks are
measurement integrity and loss of reviewer work. Existing tests pass but mostly test
synthetic, cleanly segmented input and happy-path interactions.

## Findings and concrete tasks for Claude Code

All tasks below are **open proposals**, not implemented fixes. P1 means before relying on
the workbench for an accepted baseline/intervention decision; P2 means important integrity
work before longitudinal conclusions. Use a separate engineering branch; retain the original
analysis snapshot. Do not copy private fixtures into the public repository.

### R1 · P1 · Local boundary edits erase every label in the session

Locations: `app/observer/pipeline.py:130–157`, `app/storage/repository.py:308–313`,
`app/web/app.js:341–342`.

Merge and split both route through `set_manual_boundaries`, `_write_segments`, and
`replace_observations`, deleting all observation IDs, labels, ads, eligibility, and review
states. A synthetic three-segment case with confirmed labels loses the untouched third
segment's ID and label when only the first two are merged. The UI warns before full
auto-segmentation, but not for merge/split. D-009 documents resets generally; it does not
make silent loss of unrelated human-reviewed rows acceptable for the local edit workflow.

Acceptance: unchanged intervals retain IDs, labels, provenance and review state; changed
intervals get explicit review/invalidation handling; changes are atomic. Add tests for
merge, split, cancellation/failure and preservation of an untouched reviewed interval.
Until fixed, complete boundary review before topic labelling and retain exports/backups.

### R2 · P1 · Keyword matching can fabricate DIRECT; missing topic evidence becomes UNRELATED

Locations: `experiments/EXP-001-biathlon/config.json:44`,
`app/observer/classifiers/mock.py:35–49`, `app/observer/pipeline.py:190–191`.

The inputs `Police pursuit on the highway` and `Mass start in cycling` produce DIRECT
biathlon with confidence 0.9, sufficient for auto-acceptance. A bare `Follow` UI string
produces UNRELATED even though it identifies no topic. This contradicts EXP-001's explicit
biathlon / identifiable other content criteria and can bias both numerator and unknown rate.

Acceptance: generic pursuit/mass-start/IBU contexts cannot establish DIRECT alone; UI-only,
irrelevant or incomplete text remains UNKNOWN. Add positive biathlon, adjacent winter-sport,
non-biathlon pursuit/cycling, and missing-evidence regression examples. Mock outputs must
remain unvalidated suggestions until evaluated on human-labelled content. Do not substitute
the baseline research rules for a validated production classifier.

### R3 · P1 · Detected followed-account evidence is ignored after bulk eligibility marking

Location: `app/observer/pipeline.py:210–211`; recommended UI order in README baseline steps.

Marking undetermined rows recommended, then classifying a row whose provider returns
`followed_indicator=True`, leaves it recommended. The same response changes an undetermined
row to followed_account. A synthetic classifier reproduces this with no external API.
Thus the bulk-first workflow can keep followed content in the primary denominator/numerator.

Acceptance: preserve separate evidence/provenance for bulk assumptions and explicit review;
flag a conflict or apply a justified exclusion when followed evidence is detected. Do not
silently overwrite an explicit human ruling. Test both operation orders and conflicts.

### R4 · P1 · Two undersized sessions unlock the intervention step

Locations: `app/strategist/rules.py:31–37,57–60,84–94`.

Two T0 sessions containing one confirmed eligible observation each produce `status=intervene`.
The protocol requires two samples of 50 Reels. A review-data status also still receives
intervention action suggestions and a T1 next step. Session existence is being used as a
proxy for protocol completion. This can contaminate the only chance to record a valid baseline.

Acceptance: distinguish provisional and accepted samples; gate intervention recommendations
on agreed sample size, boundary/topic review and resolved eligibility, with explicit protocol
deviations. Empty, short and unresolved sessions must not unlock T1. Missing post-intervention
samples must not be treated as measured checkpoints. Founder approves protocol exceptions.

### R5 · P2 · Corrections cannot restore unknown values and invent certainty

Location: `app/observer/pipeline.py:219–228`.

PATCH `is_ad:null` is filtered out, so an existing ad flag cannot be returned to unknown;
the UI presents this option as valid. Caption/topic fields also cannot be cleared to null.
Changing a topic to UNKNOWN sets confidence to 1.0, conflating human action with certainty.

Acceptance: omitted means unchanged; explicit null clears nullable values. Preserve review
status independently from confidence, and do not assign certainty to UNKNOWN or an uncertain
human label. Test UI-equivalent payloads and export round-trips.

### R6 · P2 · Capture-time validation and provenance are insufficient

Locations: `app/models/schemas.py` (`SessionCreate`, `ManualObservation`,
`InterventionComplete`); `app/storage/repository.py:create_session`;
`app/evaluator/metrics.py:_parse_dt`; `app/cli.py:cmd_import`.

A legal API payload containing a naive capture timestamp plus a timezone-aware completed
intervention crashes summary computation with `TypeError: can't compare offset-naive and
offset-aware datetimes`. Import also defaults capture time to now rather than the recording's
capture time; the CLI offers no capture-time argument. This distorts checkpoint order and
time to first target. The research import used MOV metadata with explicit provenance.

Acceptance: validate timezone-aware timestamps at entry, normalize chronology, reject invalid
values, and distinguish capture/import time with documented metadata fallback. Test old
recording imports, mixed offsets, missing metadata and malformed/naive times. Do not label
a sample “24h persistence” solely because its checkpoint is T3; show actual elapsed time.

### R7 · P2 · Session deletion leaves experiment-level snapshots containing deleted data

Location: `app/storage/repository.py:206–211`.

`compute_summary(store=True)` followed by `delete_session` removes session-scope metrics
but leaves an experiment-scope `metrics_json` containing that session and its statistics.
`latest_metrics` returns the stale snapshot. The documented “all derived data” deletion
contract is therefore false, even though live summary/export computations read fresh rows.

Acceptance: invalidate/delete/recompute affected experiment snapshots on deletion and on
source changes; test the underlying database, not just the live summary API. Explain retained
user-controlled exports and research sidecars separately; never delete the user's source MOV.

### R8 · P2 · Classification does not pin the profile version used

Locations: `app/observer/pipeline.py:176,199–200`, `app/services.py:export_json`,
`app/storage/db.py` (`content_observations`). Static finding.

Profile versions exist, but a classification reads the current profile and records only the
classifier version. After a profile edit, an export pairs old labels with the new profile,
without a per-classification profile version/snapshot or full model evidence history. A
rerun can change the taxonomy while retaining the same classifier identifier.

Acceptance: pin profile/taxonomy version or content hash per classification and preserve the
relevant snapshot in exports. Record classifier settings, selected frame IDs and evidence.
Regression: classify with v1, edit profile to v2, export/reclassify, verify original provenance.

### R9 · Research gate · Segmentation and deduplication need real-data validation

Locations: `app/observer/segmentation.py:detect_boundaries`,
`app/evaluator/metrics.py:51–74`. This is an acknowledged heuristic limitation, not a claimed
validated replacement algorithm.

The real recording's stock adaptive threshold combined several persistent creator changes
inside individual intervals. A high global median/MAD threshold and 3-second minimum also
cannot reliably represent rapid scrolling. Local OCR-anchor analysis found additional
candidate exposures; those boundaries still need human validation. In-content cuts must
not become new Reel exposures. First and last exposures may be partial; sampling can miss
very short exposures. The stock last segment can extend beyond the actual recording end.

A single representative-frame aHash can cluster unrelated content or miss duplicate
content at a different point in playback. Its unique-content total is an estimate. The
current primary denominator correctly retains repeated exposures; preserve that behavior.

Acceptance: founder/on-device reviewer supplies boundary reference and duplicate judgements;
report exposure count, boundary precision/recall within a specified tolerance, merge/split
errors, and uncertainty. Use multiple representative frames and UI-anchor evidence as
candidate cues only after this evaluation. Clip intervals to media duration. Keep real
fixtures local; add sanitized synthetic scrolling/cut/short-dwell tests to Git. Validate on
a separate recording before claiming generalization.

## Architecture and requirements coverage

| Requirement | Current assessment |
|---|---|
| Observe → Compare | Implemented locally; boundary and label quality remain the bottleneck |
| Strategize → Act | Rules/manual-only implementation fits feasibility scope; R4 gate required |
| Measure → Repeat | Metrics and snapshots exist; timestamp/version/deletion integrity needs work |
| New-topic learning, 20% direct target | Not tested: baseline only, no logged T1 or later sample |
| Taxonomy and eligibility separate | Schema separation is sound; R2/R3/R5 affect actual semantics |
| Unknown in denominator | Correct for eligible exposures; incomplete evidence must not become UNRELATED |
| Ad uncertainty | Nullable schema exists; eval-v1 treats null as not identified, not verified non-ad. Report it |
| Duplicate exposures | Primary exposure count preserved; aHash content counts are provisional |
| Real vs synthetic | Separate demo experiment/flags and tests; review probes never enter the real database |
| Privacy and local processing | Default gate blocks external calls; no external baseline image processing was used |
| Portability | Editable checkout tested; standard wheel does not package root experiment config (inspect before distribution) |
| Future product features | Appropriate extension points exist; no feasibility evidence yet warrants implementing them |

Additional limitations: synchronous import and non-atomic multi-step session mutation,
unbounded dependency versions, optional OCR availability/resolution, no verified live LLM
transport, and no human-labelled classifier calibration. These do not justify a new stack.
Wilson/Newcombe intervals are descriptive under independence assumptions and do not account
for classifier error, unknown labels, or feed autocorrelation.

## Local research reproduction

Run in a **fresh analysis checkout/data directory**, never over reviewed observations.
The scripts refuse to overwrite an existing baseline/report. Use an absolute source path
from the local manifest; do not publish it. FFmpeg and the macOS SDK must be installed.

```bash
.venv/bin/python -m scripts.research.pr1_review
.venv/bin/python -m scripts.research.import_baseline /absolute/path/to/recording.mov
mkdir -p data/research/BASELINE-001/frames-2fps
ffmpeg -v error -i /absolute/path/to/recording.mov \
  -vf 'fps=2:start_time=0,scale=1128:-2' -q:v 3 \
  data/research/BASELINE-001/frames-2fps/frame_%05d.jpg
swiftc -module-cache-path /tmp/amas-swift-cache scripts/research/local_vision.swift \
  -o data/research/local-vision
data/research/local-vision data/research/BASELINE-001/frames-2fps \
  data/research/BASELINE-001/local-vision.jsonl
.venv/bin/python -m scripts.research.analyze_baseline
```

macOS Vision failed to create pixel buffers inside the Codex sandbox. After explicit tool
approval, the same on-device executable succeeded outside the sandbox. This is a local OS
runtime requirement, not consent to send images elsewhere. OCR/image labels and their scores
are kept locally. Native model results may vary with OS/model revisions; retain the evidence
JSONL/hash and environment with every run.

The analysis is specific to BASELINE-001's geometry and 423 samples; it fails closed on
different input sizes/errors. It generates provisional observations in the existing schema,
full AMAS JSON and CSV exports, timestamps/boundary brackets, source checksum verification,
topic uncertainty bounds and duplicate candidates. Detailed results and the visual sheet
are private local artifacts linked from the protocol, not public research findings.
