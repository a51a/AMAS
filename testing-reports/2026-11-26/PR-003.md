## Findings for Claude Code

### C1 · P1 · Startup profile upgrade overwrites user edits

Location: `app/taste_engine/profiles.py:32–39`.

The upgrade tests only whether the biathlon keyword set matches the old shipped set, then
replaces **all topics**. Editing an adjacent topic, adding a topic, or editing the direct
topic's description, context terms or weight leaves that keyword set unchanged. On the
next `ensure_exp001` / application startup, those edits disappear from the active profile.
This contradicts D-019 and the function's promise to leave edited profiles alone. An older
version remains in profile history; that does not prevent the active configuration changing.

Reproduced: synthetic custom profile version 2 becomes 3, custom topic/adjacent keyword/
description are lost, and weight 0.35 returns to 0.20.

Acceptance: conservatively identify a genuinely unedited legacy profile, or migrate only
the shipped keyword fields while preserving every custom field/topic. Add startup and
idempotence tests for adjacent edits, added topics, weights/descriptions/context keywords,
and the untouched legacy profile. Never relabel observations silently.

### C2 · P1 · An old size deviation silently waives later review conflicts

Locations: `app/evaluator/metrics.py:88–93`; `app/api/routes.py:348–357`.

Any non-empty `deviation_note` makes an accepted non-empty session count forever, even if
its data changes after acceptance. Accept a reviewed 40-Reel sample with a note about its
short recording and a normal 50-Reel sample. Then make an observation need review and carry
an eligibility conflict. Readiness remains true. `POST /interventions` without an override
returns **200**, and no `baseline_override` is stored. The strategist says `review_data`,
so the API and strategist disagree. The old short-recording note does not authorize the
new conflict. The existing edit-after-acceptance test covers only samples without deviations.

Acceptance: bind acceptance/deviations to the reviewed data revision and their specific
scope, or invalidate acceptance on relevant edits. Require renewed acceptance or an explicit
new intervention override after a new problem. Align the API and strategist. Cover boundary
edits, reclassification, conflicts and added/deleted observations after both ordinary and
deviation acceptance. An unchanged accepted short sample should continue to work as intended.

### C3 · P2 · Reclassification deletes the new boundary audit evidence

Locations: `app/observer/pipeline.py:154–160` and `:243–247`.

Merge records the old interval and absorbed row in `classification_evidence`, then deletes
the absorbed row. Classifying the merged `needs_review` item replaces that evidence list.
In the reproduction, the absorbed ID appears immediately after merge, but disappears after
normal local mock classification; the absorbed row is already gone. The only stored merge
history is therefore lost during the documented workflow.

Acceptance: keep boundary/human provenance independently of replaceable machine evidence,
or preserve it explicitly across classification. Test merge → classify → human correction
→ export, and repeated classification; the old interval and absorbed labels/IDs must remain
auditable. Continue to preserve unaffected rows and rollback behavior.

### C4 · P2 · A baseline with zero eligible recommendations unlocks intervention

Locations: `app/evaluator/metrics.py:51–69,88–93`; `app/strategist/rules.py:105–115`.

Two accepted samples of 50 confirmed ads satisfy readiness despite **0 eligible exposures**
and `direct_share = null`. The strategist returns `intervene` with three suggested actions.
There is no measurable primary baseline to compare against. This is an uncovered validity
requirement in the new gate, not a request to remove UNKNOWN topics from the denominator.

Acceptance: require a defined primary baseline denominator before ordinary intervention
planning; report an explicit collection/review problem otherwise. Cover ads-only,
followed-only and search-only baselines and a valid eligible baseline. A founder-authorized
override may remain available with the existing explicit reason/provenance. Keep the 2×50
exposure protocol; do not silently reinterpret it as 2×50 eligible recommendations.
