## N1 · P2 · Intervention UI misses the new review-only blocking state

Locations: `app/web/app.js:467,474,488–490`, in conjunction with the expanded gate in
`app/api/routes.py:349–357`.

With two accepted, reviewed T0 samples and one pending ADHOC observation, baseline readiness
is true but the plan is `review_data`. The updated API correctly returns 409 when planning
without an override. The intervention screen, however, only checks `baseline_readiness`
when rendering its warning and override controls. It displays the Create button without a
blocking banner, checkbox or reason field. Thus the documented founder exception is
available in the API (200 with an explicit reason) but inaccessible through this UI state;
the user sees the problem only after clicking Create.

Reproduce: `.venv/bin/python -m scripts.research.pr5_review`. It creates temporary synthetic
data, uses FastAPI TestClient, and renders `viewInterventions` in Node with those actual API
responses. Observed output: ready=true, review_data, 409 without override, 200 with override,
Create present, warning/checkbox/reason absent. It does not act on the real experiment.

Acceptance: show the same gate result/reasons that the API enforces. Let the founder resolve
review items, and expose the already-supported explicit exception with a reason when
appropriate. Keep the backend gate. Add UI/API coverage for baseline-unready, baseline-ready
with other open review work, and fully ready states. This can ship with R5/R6; it is not a
new blocker to accepting the core C1–C4 fixes.
