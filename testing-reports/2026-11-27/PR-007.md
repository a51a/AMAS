## Findings

### V1 · P2 · Confirming an existing UNKNOWN retains machine confidence

Location: `app/observer/pipeline.py:407–411`.

The new correction path clears confidence when the topic changes, but not when an already
UNKNOWN machine result is confirmed. Run the local mock on "Police pursuit on the highway":
it produces UNKNOWN with confidence 0.3. The actual Confirm label payload `{confirm: true}`
returns 200 and produces `review_status=confirmed`, `target_match=unknown`, `confidence=0.3`.
JSON export retains 0.3. Explicitly PATCHing that same confidence then returns 400 because
UNKNOWN cannot carry confidence. D-026's rule therefore depends on which UI action was used.

This does not invent 1.0 or change the primary metric, but it leaves the reviewed/exported
label inconsistent with the stated R5 contract and the explicit-confidence validation.

Acceptance: when a human confirms/reviews an UNKNOWN result, normalize its exposed
confidence to null without losing `machine_label_json.confidence`. Keep omitted-field
semantics for unrelated edits. Cover local classification → Confirm label → JSON/CSV export,
as well as changing a known topic to UNKNOWN and explicitly rejecting a non-null confidence.

### V2 · P2 · Legacy observation timezone is assumed without provenance

Locations: `app/evaluator/metrics.py:283–285,356–368,414–419`.

R6 correctly normalizes legacy naive values for arithmetic, but the warning scan covers only
session `captured_at` and intervention `completed_at`. `_obs_time` preferentially uses an
observation's `observed_at`; that legacy field can also be naive. Its assumed-UTC flag is
discarded and is never propagated to the time-to-first-target result.

Reproduction: session capture `2026-06-01T10:00:00Z`, intervention `09:00Z`, first DIRECT
observation with legacy `observed_at=2026-06-01T10:05:00` (no offset). Summary reports a
measurable 1.08 hours to first target, session capture verified=true, and no timezone warning
or time-to-first timezone provenance. The display gives no indication that the exposure
clock was assumed. For a legacy local-time value, that can shift the result by a timezone/DST
offset. The existing mixed-time test also makes the session naive, so its warning hides this
separate gap.

Acceptance: track the timestamp actually used for time-to-first-target, including exposure
`observed_at` and its fallback. Warn/mark unverified when either that time or the intervention
anchor relies on a timezone assumption; preserve stored legacy values. Cover the isolated
naive-observation case with otherwise valid session/action timestamps, and an all-aware case
that remains free of assumption warnings. Do not infer a timezone or rewrite real records.
